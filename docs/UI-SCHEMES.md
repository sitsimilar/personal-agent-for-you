# 界面方案（UI Scheme）

**版本**：v2.13.1 起（2026-10-30 落地，随 v2.13.1「三套界面方案」正式发布）
> 口径更正（2026-11-13）：此处原写「v2.13.2 起」有误。界面方案在 v2.13.1 已上线（见 `docs/版本说明.md` §四 v2.13.1 行），v2.13.2 是日历互通那一版。计划表 §三 因「领先一格」整体顺延，与发行版号不再一一对应。
**代码入口**：`web/src/lib/ui-scheme.ts`（纯逻辑）· `web/src/store/uiSchemeStore.ts`（状态与持久化）

## 一、三个方案是什么

| 方案 | id | 改什么 | 影响面 | 风险 |
|---|---|---|---|---|
| 静默化 | `silent` | 视觉令牌：主色收敛、圆角三档、双层阴影、字号五档、导航降噪 | 仅视觉 | 低 |
| 分区骨架 | `zoned` | 在静默之上加布局：统一容器 1120 + 页眉带 + 首页主次分栏 + 顶栏精简 | 视觉 + 布局 | 中 |
| 流畅优先 | `fluid` | 在静默之上加交互：动效分档 + 骨架屏 + View Transitions + 命令面板 + 勾选乐观反馈 | 视觉 + 交互 | 中 |

**关键约定：三方案共用同一套视觉令牌。** 切方案时视觉基调不变，用户感知到的差异永远只有一处
（要么布局、要么交互）。这是「切换后行为清晰一致」的实现基础，也是不再出现
"颜色也变了、位置也变了"双重跳变的原因。

## 二、两个入口（都常驻，位置不随方案变化）

1. **顶栏调色板图标** —— 弹层三选一，切完停在当前页，立刻能看到变化；底部「查看三个方案的详细差异」跳到设置页锚点。
2. **设置页「界面方案」卡片**（`#ui-scheme`）—— 主入口，含改动要点、影响面、风险、同步状态与「恢复默认方案」。

## 三、防误操作的四条设计

1. **点选即生效，不弹确认框**：切换可逆、成本极低，加确认只会让用户多点一次。
2. **6 秒撤销条**：切换后底部提示带「撤销」，比"先问一遍"更省事也更安全。
3. **提示说清代价**：跨维度切换（如静默 → 分区）会点名"页面容器会收窄、首页改为左右分栏"，
   而不是含糊地说"界面已更新"。
4. **不改任何数据**：方案只影响呈现，没有数据迁移、没有不可回退的开关。

## 四、持久化（双写 + 三级降级）

| 层 | 行为 |
|---|---|
| `localStorage['pa.ui.scheme']` | 同步读写，**首帧渲染前**落地（`main.tsx` 顶部调用 `hydrateLocal()`），避免闪一下 |
| `settings.ui_scheme` | 登录后对齐；本次会话手动改过则以本地为准（不抢用户操作） |
| 列不存在 / 离线 / 写失败 | 静默退化为设备级，设置页显示「仅本机生效」，功能不受影响 |

> `settings` 行 id 由 `uiSchemeStore.setSettingsId()` 统一登记（Layout 与设置页都会调），
> 避免"设置页刚新建了一行、方案层还在用 null"导致重复 insert 撞 `owner_id` 唯一约束 23505。

## 六、新增一个方案怎么做

1. 在 `UiScheme` 类型与 `UI_SCHEME_ORDER` 里加 id；
2. 在 `FEATURES` 补齐九项能力位；
3. 在 `UI_SCHEME_META` 补展示名、一句话、影响面、风险与 4 条改动要点（`summarizeUiSchemeChange` 会自动生成切换提示）；
4. `index.css` 加 `:root[data-scheme='新id']` 变量块（没有差异化变量可省略，但必须确认默认变量就是想要的效果）；
5. `qa/ui-scheme.test.ts` 补该方案的矩阵断言 —— 三个方案的 `dimension`/`impact` 必须自洽，测试会卡住。
